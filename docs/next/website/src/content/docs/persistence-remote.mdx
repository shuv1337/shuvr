title: Persistence and remote access
description: Detach from Shuvr, reattach later, use named sessions, and connect over SSH.
---

Shuvr keeps panes running in a background server. Your terminal client can detach and reconnect later.

For the local, SSH, and `shuvr --remote` workflows, see [How to work with Shuvr](/docs/how-to-work/).

## Detach and reattach

Start Shuvr:

```bash
shuvr
```

Detach the client with `ctrl+b q`.

Your panes and agents keep running. Reattach by running Shuvr again:

```bash
shuvr
```

If you want to end the session and stop its panes, stop the default server:

```bash
shuvr server stop
```

When Shuvr starts again after a full server stop, it restores the saved session shape. For what survives detach, server restart, screen history replay, native agent session restore, and live handoff, see [Session state and restore](/docs/session-state/).

## Named sessions

Use named sessions when you want independent Shuvr servers.

```bash
shuvr session list
shuvr session attach work
shuvr session attach side-project
shuvr session stop work
shuvr session delete side-project
```

A named session has its own panes, tabs, workspaces, sockets, and runtime state. It still shares the same global config file.

Use `--json` for scripts:

```bash
shuvr session list --json
shuvr session stop work --json
shuvr session delete side-project --json
```

## Remote attach over SSH

Run Shuvr on a server and attach from any SSH client:

```bash
ssh you@server
shuvr
```

In this mode your shell is remote, Shuvr runs on the remote host, and panes keep running there after you detach.

You can also attach through SSH from your local machine:

```bash
shuvr --remote workbox
shuvr --remote ssh://you@server:2222
```

In this mode your local Shuvr is a thin client. It connects over SSH, starts or attaches to the remote Shuvr server, and streams the UI back to your local terminal. Because the client runs locally, Shuvr can bridge local desktop features such as image clipboard paste into the remote session by copying the image to a remote temp file and pasting that path.

By default, `shuvr --remote` uses your local Shuvr keybindings for that attach. This keeps local muscle memory even when the remote server has different config. The local keybindings are a snapshot from attach time; detach and reattach after editing local keybindings. Use `--remote-keybindings server` when you want the remote server config instead. Local custom command keybindings are not sent, because those commands would run on the remote host.

For repeat targets, use your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
shuvr --remote workbox
```

Remote attach supports Linux and macOS hosts on x86_64 and aarch64. Shuvr checks the remote platform, prefers a matching `shuvr` already on the remote `PATH`, then checks `~/.local/bin/shuvr`. If no matching binary exists, interactive runs prompt to install one to `~/.local/bin/shuvr`; non-interactive runs fail instead of modifying the host. If `~/.local/bin` is not on the remote `PATH`, Shuvr warns after install.

By default, remote attach uses the normal restart/stop flow if it needs to replace or restart a running remote server. To opt into experimental live handoff for a supported running remote server, pass `--handoff`:

```bash
shuvr --remote workbox --handoff
```

If you SSH into the server first and run `shuvr` there, Shuvr runs entirely on the server. That mode is useful and simple, but it cannot access your local desktop clipboard beyond normal terminal text paste.

When your local and remote platforms match, Shuvr can copy the current local binary for direct installs. For Homebrew and Nix installs, or when the platforms differ, it downloads the matching release asset for the current client version from `https://github.com/shuv1337/shuvr/latest.json`.

For local builds or custom binaries, set `SHUVR_REMOTE_BINARY` to a local file path before running remote attach.

```bash
SHUVR_REMOTE_BINARY=target/release/shuvr shuvr --remote workbox
```

## Remote named sessions

Use `--session` with `--remote` to attach to a named session on the remote host:

```bash
shuvr --remote workbox --session agents
```

## Direct terminal attach

Full Shuvr attach opens the whole workspace UI. Direct attach opens one server-owned terminal in your current terminal.

Attach by agent target:

```bash
shuvr agent attach reviewer
```

Attach by terminal ID:

```bash
shuvr terminal attach term_abc123
```

Direct attach streams the current rendered terminal state, then live ANSI frames. Input goes straight to that terminal.

Detach with `ctrl+b q`. Send a literal `ctrl+b` with `ctrl+b ctrl+b`.

Only one writable direct attach client owns input and resize for a terminal. Use `--takeover` to replace an existing owner:

```bash
shuvr terminal attach term_abc123 --takeover
```

## Single-process escape hatch

Use `--no-session` to run Shuvr without the background server/client split:

```bash
shuvr --no-session
```

This is mainly an escape hatch for debugging or compatibility. The default persistent session mode is the normal path.
